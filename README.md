# SWYNEX Monitoring and Cost Awareness

## 1. Project Overview

This project documents basic monitoring, cost awareness, and security practices for a cloud-deployed static website.

- **Deployment Platform:** GitHub Pages
- **Project:** Basic Cloud Deployment
- **Live Website:** https://dabbarabalasai-crypto.github.io/SWYNEX-Cloud-Architecture-Outline/

## 2. Monitoring and Status Checks

Monitoring helps us check whether a website is available and working correctly.

### Monitoring Steps

1. Open the deployed website in a web browser.
2. Check whether the page loads successfully.
3. Verify that the HTML content and CSS styling display correctly.
4. Open the GitHub repository and select the **Actions** tab.
5. Check the latest Pages deployment workflow and confirm whether it completed successfully.
6. If deployment fails, review the workflow logs to identify the error and fix it.

### Simple Alert Idea

Check the website and the latest deployment status once a day. If the website does not load or a deployment fails, investigate the problem and fix it.

## 3. Cost Awareness

Cost monitoring helps prevent unexpected cloud expenses.

### Cost Checklist

- Identify which cloud services are being used.
- Review the pricing and free-tier limits of each service.
- Set a budget and billing alerts when supported by the cloud provider.
- Monitor storage, data transfer, and other usage charges.
- Remove unused cloud resources.
- Review billing information regularly.

**Note:** This project uses GitHub Pages for static website hosting. Do not assume that other cloud services are deployed or that all services are free. Check the provider's current pricing and account billing details.

## 4. Security and Access-Control Checklist

- [ ] Keep GitHub account credentials private.
- [ ] Enable two-factor authentication.
- [ ] Use strong, unique passwords.
- [ ] Never upload passwords, API keys, or access tokens to the repository.
- [ ] Give collaborators only the permissions they need.
- [ ] Review repository access regularly.
- [ ] Use HTTPS when accessing the deployed website.
- [ ] Review dependencies and uploaded files before publishing.

## 5. Results

A monitoring procedure, a cost-awareness checklist, a simple alert idea, and security recommendations have been documented for the cloud deployment project.

## 6. Conclusion

This project demonstrates basic cloud monitoring practices, cost awareness, and access-control measures. These practices help improve website reliability, control cloud expenses, and protect project resources.
